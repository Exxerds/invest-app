## 3. СТЕК И АРХИТЕКТУРА (текущие решения)

### Выбранный стек
- **Frontend**: React 19 + TypeScript + Vite 8 + Tailwind CSS 4 + recharts + lucide-react + Inter Variable (шрифт ВСТРОЕН в `src/assets/fonts/`, работает офлайн)
- **Backend**: Node.js + Express (ESM)
- **Хранилище данных**: **JSON-файл** `server/data.json` (НЕ СУБД!). Причины: у заказчика на Windows (Node 24) не запускались нативные модули БД (better-sqlite3) и даже WASM (sql.js). JSON — чистый JS, работает везде. Для продакшена можно вернуть PostgreSQL
- **Auth**: JWT + bcrypt, роли RBAC: `CLIENT` / `MANAGER` / `ADMIN`
- **Письма**: nodemailer (SMTP), в dev-режиме письма сохраняются в `server/mails/` и в консоль

### Архитектура
```
Браузер (React SPA, :3000) ── /api/* (Vite proxy) ──> Express API (:4000) ──> server/data.json
```
- Запуск одной командой: `npm run dev` (concurrently: predev ставит зависимости сервера, затем API + Vite)
- JWT хранится в localStorage (`tn_token`)
- Все ошибки сервера пишутся в консоль И в файл `server/server.log`

### API (готово)
| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | Регистрация (name, email, password ≥6). Статус pending, письмо с подтверждением |
| POST | `/api/auth/confirm-email` | Подтверждение по токену → active, выдаёт JWT |
| POST | `/api/auth/login` | Вход (проверка статусов pending/blocked) |
| GET | `/api/auth/me` | Текущий пользователь по Bearer-токену |
| POST | `/api/auth/forgot-password` | Письмо со ссылкой сброса (1 час) |
| POST | `/api/auth/reset-password` | Новый пароль по токену |
| GET | `/api/admin/users` | Список пользователей (только ADMIN) |
| POST | `/api/admin/users/:id/password` | **Смена пароля ЛЮБОМУ пользователю** (только ADMIN) |
| PATCH | `/api/admin/users/:id` | Блокировка/разблокировка/роль (только ADMIN) |
| GET | `/api/health` | Проверка сервера |

### Демо-пользователи (создаются автоматически при старте сервера — seed.js)
- **ADMIN**: `admin@trade.io` / `admin123`
- **MANAGER**: `manager@trade.io` / `manager123`
- **CLIENT**: `client@trade.io` / `client123`
- Плюс в модалке входа есть 3 кнопки «Demo Admin/Manager/Client» — вход БЕЗ сервера (локально в браузере)

### Этап 6.14. ГОТОВНОСТЬ К VERCEL: POSTGRES ВМЕСТО ФАЙЛА ✅ (16.08.2026)
> Заказчик: «деплой делаю на Vercel, всё должно работать после деплоя, а не только локально».
> **Проблема, которую это вскрыло:** Vercel — serverless. Нет постоянного сервера и нет диска
> для записи. Прежний бэкенд на `data.json` там терял бы КАЖДУЮ регистрацию.

**Что было бы сломано на Vercel и как исправлено:**
| Сломалось бы | Решение |
|---|---|
| `data.json` — файловая система только для чтения | **PostgreSQL**. Новый слой `server/src/db.js`: есть `DATABASE_URL` → база, нет → JSON-файл. Один и тот же API |
| Документы KYC в `server/uploads/` | На Vercel файл хранится в БД рядом с метаданными, локально — по-прежнему на диске |
| `server.log` — падал бы при первой записи | Запись в файл отключается по флагу `VERCEL`, логи идут в консоль (Vercel их собирает) |
| Защита от перебора паролей на `setInterval` | Таймер убран: очистка происходит лениво при запросе |
| `app.listen()` не запускается в serverless | Приложение экспортируется, `listen` только вне Vercel. Точка входа `api/index.js` |
| Схема БД | Таблицы и индексы создаются автоматически при первом запросе |

**Технические детали:**
- [x] Все обращения к хранилищу переведены на **async/await** (auth, admin, kyc, notifications, seed) —
      иначе с реальной БД возвращались бы промисы вместо данных
- [x] `vercel.json`: сборка сайта, маршрут `/api/*` → функция, остальное → SPA
- [x] `api/index.js`: seed выполняется один раз на инстанс, без дублей пользователей
- [x] Бинарник документа никогда не уходит в API-ответ (проверено отдельным тестом)
